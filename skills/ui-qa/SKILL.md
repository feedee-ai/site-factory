# ui-qa — перевірка інтерфейсу перед деплоєм

Мета: Александр не має знаходити UI-баги після того, як ти сказав «готово». Цей скіл — ворота перед продом. **Деплой на прод без зеленого ui-qa заборонений.**

## Коли запускати
- Завжди останнім кроком перед `vercel deploy --prod` (у `/new-site`, `/deploy`, `/rebuild-site` і будь-якій правці сайту).
- Після будь-якої правки CSS/верстки, перш ніж писати «готово».
- Коли користувач надіслав скрін бага — спершу відтвори його прогоном, потім виправ, потім прогін ще раз.

## 1. Автоматичний прогін

```bash
node ~/.claude/skills/ui-qa/scripts/ui-qa.mjs site --out qa-report          # повна матриця, ~15–25 хв
node ~/.claude/skills/ui-qa/scripts/ui-qa.mjs site --quick --out qa-report  # 7 ключових екранів — для ітерацій
node ~/.claude/skills/ui-qa/scripts/ui-qa.mjs https://preview-url.vercel.app --out qa-report  # або за адресою
```
Запускай у фоні (`run_in_background`), він довгий. Код виходу: `0` — блокерів немає, `1` — є блокери, `2` — збій запуску.
Під час ітерацій — `--quick`; **перед деплоєм — повна матриця**.

Екрани: 320×568, 360×780, 375×667, 390×844, 393×852, 412×915, 430×932, телефони горизонтально 844×390 і 932×430, 600×960, 768×1024, 820×1180, 1024×768, 1024×1366, 1280×720, 1366×768, 1440×900, 1536×864, 1920×1080, 2560×1440. Плюс 390 і 1440 з `prefers-reduced-motion`, плюс 390 без JS.
На кожному екрані сторінка проходиться екран за екраном, відкриваються всі `<details>` і `[aria-expanded]`, виконуються кроки з конфігу.

### Що блокує деплой
| Перевірка | Як ловиться |
|---|---|
| Горизонтальний скрол | ширина документа з **знятим** `overflow-x: clip/hidden` на html/body — iOS Safari інакше показує скрол убік |
| Вихід за край екрана | будь-який видимий елемент лівіше 0 чи правіше ширини, не обрізаний предком |
| Текст вилазить з коробки | `scrollWidth > clientWidth` у листка з `overflow: visible` (nowrap у кнопках, довгі слова) |
| Накладання тексту | перетин рамок двох текстових листків > 25%; рядки при `line-height` < шрифту |
| Контраст | за пікселями знімка під рядками тексту: < 3:1 звичайний / < 2.2:1 великий — блокер, < норми WCAG місцями — попередження |
| Іконка не по центру | центр «чорнила» в круглому знаку зсунутий > 22% (плюс у кружку, стрілка тощо) |
| Зона натискання | на сенсорних екранах < 32px — блокер, < 44px — попередження |
| Перекрито фіксованим шаром | кнопку/поле закриває шапка чи нижній док, і прокруткою з-під нього не вивести |
| Картинки | биті, незавантажені після прокрутки до них |
| Мережа і JS | помилки консолі, JS-винятки, відповіді 4xx/5xx |
| Перший екран | немає H1 або головна кнопка дії не видна на першому екрані |
| Дрібний шрифт | < 9px на сенсорних (11px — попередження) |

Попередження (не блокують, але виправ, якщо дешево): дрібний шрифт 9–11px, кнопки 32–44px, розтягнуті картинки, CLS при завантаженні > 0.1, доступність (alt, назви кнопок, підписи полів, `lang`).

## 2. Перегляд очима — обов'язково
Автоматика не бачить усього. Відкрий **кожен** аркуш `qa-report/sheets/*.jpg` (Read) і пройди чек-лист:
- нічого не обрізано, не налізає, не «пливе» відносно сітки; відступи симетричні;
- іконки, стрілки, плюси в кружках — по центру; кнопки одного ряду однакової висоти;
- текст на фото читається; на телефоні перший екран не завалений текстом (заголовок + 1–2 рядки);
- флекс/грід: при звуженні елементи переносяться акуратно, а не стискаються в овали і не виштовхують сусідів;
- шапка, док і модалки не закривають контент; бургер-меню відкривається і закривається;
- у шоурумах/слайдерах/формах — стани після взаємодії виглядають правильно (скріни `i-*.jpg`).
Будь-що з цього, знайдене очима, — це теж блокер.

## 3. Виправлення без нових багів (флекс і грід)
- Діти флекс/грід-контейнерів, що містять текст: `min-width: 0`; колонки — `minmax(0, 1fr)`, не `1fr`.
- Іконки/кружки у флексі: `flex: none` + явні `width/height/min-width`, псевдоелементи центрувати від **свого** кружка (`position: relative` на кружку, `left/top: 50%` + від'ємні margin або `translate`).
- Кнопки на вузьких екранах: дозволити перенос (`white-space: normal`, `height: auto`, `min-height`) або коротший підпис для `≤ 420px`, а не `nowrap`.
- `input[type=range]` має власні поля 2px — `margin: 0`.
- Текст на фото — у темній зоні кадру + градієнт/тінь під ним; не довіряй «на око», дивись звіт контрасту.
- Не ховай вихід за край через `overflow: hidden` на `body` — шукай джерело. `overflow-x: clip` на секціях — лише як страховка.
Після виправлень — повторний прогін, доки не буде `✅ ГОТОВО ДО ДЕПЛОЮ` і чистого перегляду очима.

## 4. Конфіг проєкту (необов'язково) — `ui-qa.config.json` поруч із `site/`
```json
{
  "primaryCta": ".hero [data-lead]",
  "ignore": [".decor-marquee"],
  "contrastIgnore": ["shot__badge"],
  "interactions": [
    { "name": "меню", "click": "[data-burger]", "viewports": "mobile", "close": "[data-burger]" },
    { "name": "заявка", "click": "[data-lead]", "close": "[data-sheet-close]" },
    { "name": "шоурум-трек", "click": "[data-mode=track]" }
  ]
}
```
`ignore` — лише для свідомих декоративних виходів за край; ніколи не глуши так справжній баг.

## 5. Що сказати користувачу
Коротко: «UI-QA: ✅ N екранів, 0 блокерів» + що виправлено за прогін + попередження, які свідомо лишені й чому. Без зеленого прогону не писати «готово» і не деплоїти на прод.
